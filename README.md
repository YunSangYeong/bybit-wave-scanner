# WAVE — Bybit 1파 탐지기 v1.1

Bybit USDT 무기한 선물에서 거래대금 급증을 동반한 상승·하락 1파를 찾고 이후 눌림·되돌림을 추적하는 모바일 웹 앱입니다. React + TypeScript + Vite로 구현하며, 브라우저에서 Bybit V5 Public API를 직접 호출합니다. 서버, 로그인, API Key, 자동 주문은 없습니다.

## 시작하기

Node.js **22.12 이상** 또는 **24 이상**이 필요합니다. CI는 Node 22를 사용합니다.

```sh
npm ci
npm run dev
```

개발 서버에서 `/bybit-wave-scanner/` 경로를 엽니다. 접속 시 최근 3시간을 자동 검색합니다. 변경한 검색 설정은 브라우저에만 저장되어 다음 접속 때 재사용됩니다. 신호·시장 데이터는 저장하거나 만들어 표시하지 않으며 매번 API에서 다시 가져옵니다. 웹페이지를 닫은 동안 검색은 진행되지 않습니다. 켜 둔 상태에서도 자동 반복 검색하지 않으므로 최신 정보가 필요하면 새로고침하세요.

```sh
npm test          # 탐지, API, 전체 검색 단위 테스트
npm run build    # TypeScript 검사 + dist 생성
npm run preview  # 배포 결과 확인
```

권한 제한된 클라우드에서 npm 기본 캐시를 쓸 수 없다면 `npm ci --cache /workspace/.npm-cache`를 사용합니다.

## 탐색 범위와 데이터

- `/v5/market/time`의 거래소 시각으로 검색 기준을 고정합니다. 기기 시계가 틀려도 미확정봉을 신호로 쓰지 않습니다.
- `/v5/market/instruments-info?category=linear&status=Trading&limit=1000`을 `nextPageCursor`가 없어질 때까지 조회합니다. `LinearPerpetual`, `USDT`, `Trading`만 포함합니다.
- `/v5/market/tickers?category=linear`의 `turnover24h`로 유동성을 필터링합니다. 기본 1,000만 USDT, 화면의 입력 단위는 **만 USDT**입니다 (기본 입력값 1000).
- `/v5/market/kline`의 `interval=5`, **7번째 필드 `turnover` (USDT)**를 사용합니다. 6번째 필드의 코인 수량을 RVOL로 쓰지 않습니다.
- 최근 1 / 3 / 6시간에 **봉 마감 시각**이 포함되는 모든 봉과 이전 기준봉 20개를 확보합니다. 최대 93개의 봉이 필요하므로 한 종목당 한 요청으로 충분합니다.
- 응답은 시간순으로 정렬하고 가격·거래대금·중복·누락·조회 범위를 검사합니다. 미확정봉은 제외합니다. 신규 상장 등으로 기준봉이 부족하면 그 종목은 조회 실패로 표시합니다.

**유동성 필터는 검색 시점의 24시간 거래대금 스냅샷입니다.** V5 ticker는 과거 시점의 24h 스냅샷을 제공하지 않으므로 이 앱은 역사적 유동성까지 복원하는 백테스터가 아닙니다. 과거 1파의 가격·돌파·RVOL 계산에는 미래 캔들을 사용하지 않습니다. 현재 상장·거래 중인 종목만 검색합니다.

## 1파 계산

확정봉 `i`에서 다음을 모두 만족하면 신호가 됩니다.

1. `(close[i] / close[i-3] - 1) × 100 ≥ 최소 상승률` (기본 2%, 롱).
2. `turnover[i] / mean(turnover[i-20 ... i-1]) ≥ 최소 RVOL` (기본 3배).
3. `close[i] > max(high[i-20 ... i-1])`.
4. 검색 시점의 24h 유동성 필터 통과.

평균에는 신호봉을 포함하지 않습니다. 기준봉이 연속되지 않거나 평균 거래대금이 0이면 계산하지 않습니다. 발생 시각은 신호봉의 **마감 시각**이며 모든 화면 시간은 KST입니다. 신호 당시 1시간 수익률은 `close[i] / close[i-12] - 1`이며 **12% 초과**일 때 과열을 표시합니다.

동일 파동은 검색 범위 내 신호를 시간순으로 묶고 최초 신호를 표시합니다. 시작 저점은 신호봉을 포함한 최근 3개 봉의 최저가입니다. 시작 저점 이탈 또는 기존 최고가에서 상승폭의 50% 이상 되돌림이 발생하면 이후 새 돌파는 별도 파동으로 취급합니다. 묶인 추가 신호 수는 상세 화면에 표시합니다. 범위 경계 이전의 파동까지 식별하는 방식은 아닙니다.

롱 탐지 점수 (0~100)는 `min(40, 상승률/설정 상승률 × 20) + min(40, RVOL/설정 RVOL × 20) + 비과열 20점`입니다. 정렬용 기준이며 수익 확률·매수 신뢰도가 아닙니다.

## 눌림·거줄음 상태

과거 신호를 확정한 뒤 별도로 신호 이후부터 검색 기준 시점까지의 확정봉을 분석합니다.

- 최고가: 신호봉 이후의 최고 `high`. 동일 고점은 먼저 발생한 봉을 기준으로 합니다.
- 조정률: `(1 - 최근 확정 종가 / 최고가) × 100`. 실시간 호가·마지막 체결가가 아닙니다.
- 1파 평균 거래대금: 시작 저점 봉부터 최고가 봉까지의 평균.
- 조정 평균 거래대금: 최고가 **다음 봉부터** 최신 확정봉까지의 평균. 조정봉이 없으면 값은 미정입니다.
- 거래대금 비율: 조정 평균 / 1파 평균.

| 상태 | 조건 (위쪽이 우선) |
| --- | --- |
| 구조 무효 | 신호 이후 한 번이라도 시작 저점 미만의 저가 발생 |
| 반등 관찰 | 거줄음 조건 + 조정봉 2개 이상 + 최신 양봉 종가가 직전 봉 고가 돌파 |
| 거줄음 확인 | 조정 평균이 1파 평균의 70% 이하 + 조정 구간에 음봉 존재 |
| 눌림 진행 | 최고가 이후 확정봉 존재 |
| 1파 발견 | 최고가 이후 확정봉 없음 |

70% 감소 기준과 50% 파동 분리 기준은 v1.0의 명시적 휴리스틱입니다. **거줄음은 후보이며 반등·하락 재개 관찰도 매수·매도 확정 신호가 아닙니다.** 봉 내부 가격의 진행 순서는 OHLC로 알 수 없으므로 최고가가 발생한 봉 내부의 조정은 별도로 계산하지 않습니다. 구조 무효는 이후 상승해도 유지됩니다.

## 안정성과 CORS

종목 검색 작업은 최대 4개가 진행되지만 모든 요청·재시도는 하나의 큐에서 **200ms 간격**으로 출발합니다. 각 요청은 12초 제한, 최대 3회 시도입니다. HTTP 429·5xx, Bybit 10006·10016·10000은 지수 대기와 `Retry-After`를 반영합니다. HTTP 403은 반복 호출하지 않고 현재 검색의 후속 요청에도 접근 거부로 기록합니다.

개별 종목 실패 시 성공한 결과만 표시하고 **부분 검색 결과**와 실패 종목·원인을 보여 줍니다. 종목 목록이나 거래소 시각 조회 실패 시 전체 검색 실패를 표시합니다. 이전 성공 결과가 남아 있다면 이전 검색임을 명시합니다. 실패를 신호 없음으로 숨기거나 가짜 API 응답으로 대체하지 않습니다.

필요한 외부 호스트는 `api.bybit.com`입니다. GitHub Pages에서도 브라우저가 직접 접속하므로 사용자 지역 제한과 Bybit의 CORS 응답 정책이 적용됩니다. Vite 개발 프록시나 비공식 공개 프록시를 사용해 로컬에서만 성공하는 구성을 만들지 않았습니다. `Failed to fetch`는 CORS, 네트워크, 지역 제한 모두에서 발생할 수 있으므로 개발자 도구의 Network 응답을 함께 확인하세요. `no-cors` 모드로는 데이터를 읽을 수 없습니다.

**현재 검증 환경의 한계:** 클라우드에서 실제 `api.bybit.com` 호출은 CloudFront의 HTTP 403 국가 차단 응답을 반환합니다. 따라서 이 환경에서는 실제 종목 전체 검색 성공과 정상 응답의 CORS 허용을 검증할 수 없었습니다. 허용 지역의 스마트폰에서 배포 페이지를 열어 Network 탭의 성공 응답과 전체 검색 완료를 추가 확인해야 합니다. 접근 불가 환경에서 데이터가 보이는 것처럼 우회하거나 꾸미지 않습니다.

## 모바일 브라우저 검사

프로덕션 빌드를 preview로 실행한 상태에서:

```sh
npm run build
npm run preview -- --port 4173
# 다른 터미널:
npm run test:browser
```

Playwright는 기본 `/usr/bin/chromium`을 사용합니다. 경로가 다르면 `CHROMIUM_PATH`를 지정하세요. 서버 주소는 `TEST_BASE_URL`로 변경할 수 있습니다. 테스트는 **테스트 전용 합성 응답**으로 360/375px 모바일과 데스크톱, 자동 검색, 상세 차트·봉 선택, 상태 필터, 설정 저장, 새로고침, 부분 실패를 검사합니다. 합성 데이터는 앱 번들에 포함되지 않습니다. 마지막에는 별도 컨텍스트에서 **실제 Bybit 요청**을 시도하고 접속 결과를 보고합니다. 스크린샷은 ignored `test-results/`에 생성됩니다. 이는 실제 iOS/Android 기기에서의 성공 검증을 대신하지 않습니다.

실기기 점검: 페이지 최초 진입 → 전체 검색 완료와 실패 수 확인 → 종목 선택 → 차트 좌우 스크롤·봉 이동 → 설정 변경·새로고침 → 페이지 닫기·재접속 후 과거 재검색 확인. 검색 결과는 가격이 빠르게 바뀔 수 있으므로 항상 Bybit 원본 차트를 직접 검토하세요.

## GitHub Pages 배포

`vite.config.ts`의 `base`는 저장소 경로에 맞춘 `/bybit-wave-scanner/`입니다. 저장소 이름을 바꾸거나 사용자 도메인을 사용하면 `base`도 조정하세요.

1. 저장소 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 선택합니다.
2. 변경 파일을 `main`에 커밋·푸시합니다.
3. `.github/workflows/pages.yml`이 `npm ci → npm test → npm run build` 후 `dist`를 Pages로 배포합니다. Actions 탭에서 수동 실행도 가능합니다.
4. 성공 후 Pages가 제공하는 주소를 스마트폰에서 열고 실제 API 접근과 검색 완료를 확인합니다.

배포 주소: `https://yunsangyeong.github.io/bybit-wave-scanner/`. 현재 버전의 배포 성공 여부는 Actions 탭에서 확인하세요.


## v1.1 — 롱·숏 양방향 탐지

동일한 확정 5분봉을 한 번 조회해 롱과 숏을 함께 계산합니다. API 호출 수는 방향 추가로 늘어나지 않습니다. 기본 결과는 양방향이며 **전체 방향 / 롱 / 숏** 필터로 볼 수 있습니다. 필터는 이미 검색한 결과를 고르므로 추가 검색 없이 바뀝니다. 방향별 파동 묶기 상태는 독립적입니다. 같은 종목에서 서로 다른 시각의 롱·숏이 각각 발견될 수 있으며 상단 종목 수는 중복 종목을 한 번만 셉니다.

| 항목 | 롱 | 숏 |
| --- | --- | --- |
| 15분 가격 조건 | 종가가 3개 봉 전보다 설정률 이상 상승 | 종가가 3개 봉 전보다 설정률 이상 하락 |
| 돌파 조건 | 종가 > 직전 20봉 최고 고가 | 종가 < 직전 20봉 최저 저가 |
| 거래대금 / 유동성 | 동일한 RVOL·24h USDT 필터 | 동일한 RVOL·24h USDT 필터 |
| 시작 기준 | 신호봉 포함 최근 3봉 최저가 | 신호봉 포함 최근 3봉 최고가 |
| 파동 끝점 | 신호봉 이후 최고 고가 | 신호봉 이후 최저 저가 |
| 조정·되돌림률 | (1 − 최신 확정 종가 / 최고가) × 100 | (최신 확정 종가 / 최저가 − 1) × 100 |
| 거줄음 확인 | 평균 거래대금 70% 이하 + 음봉 | 평균 거래대금 70% 이하 + 양봉 |
| 재개 관찰 | 양봉 종가가 직전 봉 고가 돌파 → 반등 관찰 | 음봉 종가가 직전 봉 저가 이탈 → 하락 재개 관찰 |
| 구조 무효 | 이후 저가 < 시작 저점 | 이후 고가 > 시작 고점 |
| 과열 | 신호 당시 1h 상승률 > 12% | 신호 당시 1h 하락 폭 > 12% |

숏은 고점 이후의 눌림 대신 **저점 이후의 되돌림**을 추적하며 아직 거줄음 조건을 충족하지 않으면 ‘되돌림 진행’으로 표시합니다. 숏 조정 구간은 최저가 다음 봉부터 계산합니다. 평균 거래대금 계산, 기준점의 동일 가격 접촉을 무효로 보지 않는 규칙, 한 번 무효가 되면 유지되는 규칙, 50% 되돌림 이후 새 파동 분리도 방향을 반대로 적용합니다.

카드의 숏 1파 하락률과 상세 1시간 등락률은 음수로 표시합니다. 최소 15분 상승·하락률 설정은 양의 크기(기본 2%)를 입력하며 두 방향에 동일하게 적용합니다. 점수는 해당 방향의 움직임 크기를 사용하므로 숏의 음수 수익률 때문에 감점되거나 음수 점수가 나오지 않습니다. 예: −3% 하락, RVOL 4배, 비과열은 롱의 +3%와 같은 77점입니다. 방향·상태·차트 설명은 후보 관찰용이며 매매 확정 신호가 아닙니다.
